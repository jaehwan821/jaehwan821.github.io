VERSION CONTROL / QUICK GUIDE

Git을 배우면
코드의 시간을 관리할 수 있습니다.

Git은 파일의 변경 이력을 기록하고, 여러 사람이 같은 프로젝트를 안전하게 협업하도록 도와주는 분산 버전 관리 시스템입니다.

01

Git의 핵심 개념

작업한 파일을 바로 공유하는 대신, 변경 내용을 단계적으로 기록한 뒤 원격 저장소와 동기화합니다.

저장소 Repository

프로젝트의 파일과 모든 변경 이력을 저장하는 공간입니다. 로컬 저장소와 GitHub 같은 원격 저장소가 있습니다.

커밋 Commit

특정 시점의 변경 내용을 하나의 기록으로 남기는 작업입니다. 커밋 메시지는 무엇을 바꿨는지 분명하게 작성합니다.

브랜치 Branch

기존 코드에 영향을 주지 않고 기능을 개발하는 작업 공간입니다. 완성한 뒤 main 브랜치에 병합합니다.

02

기본 작업 흐름

1. 수정파일을 만들거나 코드를 변경합니다.
2. 스테이징커밋할 변경을 선택합니다.
3. 커밋변경 내용을 로컬 이력에 기록합니다.
4. 푸시원격 저장소에 업로드합니다.
git status
git add index.html
git commit -m "페이지 내용 수정"
git push origin main
03

자주 사용하는 명령어

git init

현재 폴더를 새로운 Git 저장소로 초기화합니다.

git clone URL

원격 저장소를 컴퓨터에 복사하고 연결합니다.

git status

수정된 파일, 스테이징된 파일, 현재 브랜치를 확인합니다.

git add 파일명

지정한 파일을 다음 커밋에 포함하도록 스테이징합니다. 모든 파일은 git add .으로 선택할 수 있습니다.

git commit -m "메시지"

스테이징된 변경 내용을 로컬 저장소에 기록합니다.

git log

이전 커밋의 작성자, 날짜, 메시지와 변경 이력을 확인합니다.

git diff

아직 커밋하지 않은 변경 내용을 줄 단위로 비교합니다.

git pull

원격 저장소의 최신 변경 내용을 내려받아 현재 브랜치에 반영합니다.

git push origin 브랜치명

로컬 커밋을 원격 저장소에 업로드합니다.

git branch 브랜치명

새 브랜치를 만들고, git switch 브랜치명으로 이동합니다.

git merge 브랜치명

다른 브랜치의 변경 내용을 현재 브랜치에 합칩니다.

04

처음 시작할 때

# 사용자 정보 설정
git config --global user.name "이름"
git config --global user.email "email@example.com"

# 프로젝트 내려받기
git clone https://github.com/사용자명/저장소명.git
cd 저장소명

# 변경 기록 남기기
git add .
git commit -m "첫 번째 커밋"
git push origin main
주의: git add .을 실행하기 전에 git status로 비밀번호, API 키 같은 민감한 파일이 포함되지 않았는지 확인하세요. 필요한 파일은 .gitignore에 등록합니다.
작은 커밋을 자주 남기면 변경 이력을 이해하기 쉬워집니다.
